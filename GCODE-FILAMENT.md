# Filamentverbrauch im G-Code — Inhaltsreferenz

Rein informativ: **was** ein G-Code (Snapmaker A350, Slicer **Snapmaker Orca** / OrcaSlicer-Fork)
über den Filamentverbrauch enthält und **wie diese Daten strukturiert** sind. Keine
Implementierungsvorgaben.

---

## 1. Wo die Daten stehen

Jede Zeile beginnt mit `;`. Es gibt **zwei** Blöcke mit **unterschiedlicher Syntax** — verifiziert
an vier echten Dateien aus Snapmaker Orca 2.3.4 (30.07.2026).

**Oben, `HEADER_BLOCK_START … HEADER_BLOCK_END`** — wenige Zeilen, Format `key: wert`
(**Doppelpunkt**). Slicer-Kennung, Layerzahl, Bauhöhe, Dichte, Durchmesser:
```gcode
; HEADER_BLOCK_START
; generated by Snapmaker Orca 2.3.4 on 2026-07-30 at 10:47:39
; total layer number: 56
; filament_density: 1.24,1.24,1.24,1.24
; filament_diameter: 1.75,1.75,1.75,1.75
; max_z_height: 11.30
; HEADER_BLOCK_END
```
Direkt danach folgt ein `THUMBNAIL_BLOCK` mit einem base64-PNG (300×150) in Kommentarzeilen.

**Unten, gegen Dateiende** — Verbrauchsstatistik und der komplette Config-Dump, Format
`key = wert` (**Gleichheitszeichen**):
```gcode
; <key> = <wert(e)>
```

⚠️ Derselbe Schlüssel kann in **beiden** Blöcken stehen: `filament_density` erscheint oben mit
Doppelpunkt und unten mit Gleichheitszeichen. Wer nur `=` erkennt, liest den unteren Block —
und der enthält alles Nötige.

**Lage des unteren Blocks:** in der Beispieldatei (2 698 726 Bytes) reicht er von Byte 2 675 081
(`filament used [g]`) bis 2 682 449 (`filament_vendor`), also die letzten ~24 KB. Die Länge des
Config-Dumps hängt an den Einstellungen (eigenes Start-/End-G-Code landet dort mit drin) und ist
**nicht** konstant. Wer nur den Tail liest, muss prüfen, ob alle Pflicht-Schlüssel gefunden wurden,
und andernfalls weiter aufziehen.

## 2. Verbrauchswerte (reales Beispiel)

Aus einem echten File (4 Filament-Slots im Projekt definiert, nur Slot-Index 1 tatsächlich benutzt):

```gcode
; filament used [mm] = 0.00, 15398.04, 0.00, 0.00
; filament used [cm3] = 0.00, 37.04, 0.00, 0.00
; filament used [g] = 0.00, 45.93, 0.00, 0.00
; total filament used [g] = 45.93
; total filament cost = 0.69
```

| Key | Inhalt |
|---|---|
| `filament used [g]` | Verbrauch **je Slot** in Gramm (dichte-korrekt) |
| `filament used [mm]` | Filamentlänge je Slot in mm (Strang, nicht Extrudat) |
| `filament used [cm3]` | Volumen je Slot in cm³ |
| `total filament used [g]` | Summe über alle Slots |
| `total filament cost` | Kosten (aus `filament_cost` × Verbrauch) |

Quer-Check der Konsistenz: `used[g] = used[cm3] × filament_density` → 37.04 × 1.24 = 45.93 ✓.

## 3. Struktur der Arrays

- **Positionsgleiche Arrays, 0-basiert.** Position `i` = **Tool `T{i}`**. Alle filament-bezogenen
  Arrays sind gleich lang (= Anzahl im Projekt definierter Filament-Slots) und index-parallel:
  ```
  used_g[i] ⟷ used_mm[i] ⟷ used_cm3[i] ⟷ filament_settings_id[i] ⟷ filament_colour[i] ⟷ Ti
  ```
  Beispiel oben: Index 1 → `T1` → „DEEPLEE PLA PRO Rosa" (#F19CB4) → 45.93 g.
- **Nicht benutzte Slots stehen auf `0`.** Nur Slots mit Wert `> 0` wurden gedruckt.
- **Delimiter sind uneinheitlich (wichtig beim Parsen):**
  - Zahlen-Arrays (`filament used [mm|cm3|g]`, `filament_density`, `filament_diameter`) → **Komma** `,`
  - String-Arrays (`filament_settings_id`, `filament_colour`, `filament_type`, `filament_vendor`) → **Semikolon** `;`
  - `filament_settings_id`-Werte sind zusätzlich **in Anführungszeichen** (`"…"`) und können selbst
    Sonderzeichen enthalten.

## 4. Identität je Slot (im selben Block)

```gcode
; filament_settings_id = "DEEPLEE Basic PLA Beige";"DEEPLEE PLA PRO Rosa";"DEEPLEE PLA+ Weiß";"DEEPLEE Basic PLA Blau-Grau"
; filament_colour = #D8C6A1;#F19CB4;#FFFFFF;#6E8394
; filament_type = PLA;PLA;PLA;PLA
; filament_vendor = Snapmaker;Snapmaker;Snapmaker;Snapmaker
; filament_density = 1.24,1.24,1.24,1.24
; filament_diameter = 1.75,1.75,1.75,1.75
```

| Key | Inhalt |
|---|---|
| `filament_settings_id` | Preset-/Filamentname je Slot (eindeutigste Kennung) |
| `filament_colour` | Farbe je Slot als `#RRGGBB` |
| `filament_type` | Materialtyp je Slot (PLA, TPU, …) |
| `filament_vendor` | Hersteller je Slot (aus dem Preset geerbt; nicht zwingend der reale Händler) |
| `filament_density` | Dichte je Slot in g/cm³ |
| `filament_diameter` | Nenndurchmesser je Slot in mm |

---

## 5. Was in den Verbrauchswerten enthalten ist

- `filament used [g]` je Slot ist das **gesamte Extrudat dieses Filaments** — inklusive
  Skirt/Brim, Support, Prime-Line, Wipe und (bei Mehrfarbe) Flush-/Purge-Mengen.
- Es gibt **keinen separaten „Abfall"-Posten**; Modell- und Verbrauchsanteil sind nicht getrennt
  ausgewiesen.
- Bei Mehrfarbdrucken ist der Spül-/Purge-Verbrauch bereits den Slot-Werten zugerechnet
  (die genaue Zurechnung einzelner Spülmengen kann geringfügig schwanken).

## 7. Wenn die Verbrauchskommentare fehlen

Nicht jeder G-Code enthält die `; filament used …`-Zeilen (z. B. anderer Slicer, reduzierter
Export). Dann ist der Verbrauch **nur** in den E-Achsen-Bewegungen enthalten. Fakten dazu:

- Extrusionsmodus: `M82` = absolut, `M83` = relativ. **Snapmaker Orca nutzt relative Extrusion (`M83`).**
- `G92 E0` setzt den E-Nullpunkt zurück (relevant nur im Absolut-Modus).
- In `G0`/`G1`-Zeilen ist `E` der Extrusionswert; **negative E = Retraction** (kein Materialverbrauch).
- Länge↔Gewicht-Zusammenhang: `g = länge_mm × π × (diameter/2)² × density / 1000`
  (`diameter`, `density` stehen im Kopf, je Filament).
- Bei mehreren Werkzeugen wechselt der aktive Extruder über `T0`…`T3`; E-Beträge gehören zum jeweils
  aktiven Tool.

---

## 8. Slicer-Unterschiede (Kennung im Header)

- **Snapmaker Orca / OrcaSlicer**: `; generated by Snapmaker Orca …` bzw. `OrcaSlicer` — Keys wie oben
  (`; filament used [g] = …`, semikolon-/komma-getrennte Arrays).
- **Snapmaker Luban / Cura**: abweichende Kommentare (z. B. Luban `;Filament used: X.Xm`), i. d. R.
  **keine** `[g]`-Aufschlüsselung je Slot.

## 9. Referenz — verbrauchsrelevante Keys (Orca)

| Key | Typ | Delimiter |
|---|---|---|
| `filament used [g]` | Zahl je Slot (g) | Komma |
| `filament used [mm]` | Zahl je Slot (mm) | Komma |
| `filament used [cm3]` | Zahl je Slot (cm³) | Komma |
| `total filament used [g]` | Skalar (g) | — |
| `total filament cost` | Skalar | — |
| `filament_settings_id` | String je Slot (quoted) | Semikolon |
| `filament_colour` | `#RRGGBB` je Slot | Semikolon |
| `filament_type` | String je Slot | Semikolon |
| `filament_vendor` | String je Slot | Semikolon |
| `filament_density` | Zahl je Slot (g/cm³) | Komma |
| `filament_diameter` | Zahl je Slot (mm) | Komma |
| `filament_cost` | Zahl je Slot (**Währung pro kg**) | Komma |

**`filament_cost` verifiziert** an vier Dateien (Werte `13.59,13.59,11.99,13.59`):
`total filament cost` = Σ über alle Slots von `used[g] × filament_cost ⁄ 1000`.

| Job | Slot | Verbrauch | Preis/kg | gerechnet | im G-Code |
|---|---|---|---|---|---|
| Assembly | 0 | 37,57 g | 13,59 | 0,5106 | 0,51 |
| ElefantMobile 2h14 | 3 | 18,84 g | 13,59 | 0,2560 | 0,26 |
| ElefantMobile 4h25 | 1 | 45,93 g | 13,59 | 0,6242 | 0,62 |
| Ivana | 2 | 1,98 g | **11,99** | 0,0237 | 0,02 |

Die Ivana-Zeile belegt die Index-Parallelität auch für `filament_cost`: sie nutzt Slot 2 und
rechnet mit 11,99, nicht mit 13,59.
